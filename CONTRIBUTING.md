# Contributing

Thanks for helping. Three kinds of contribution are welcome: adding a tool to the list,
fixing a fact, and improving the site.

## Adding a tool to the list

The list lives in **`src/content/list.ts`**, not in the README or in the page — those are both
generated from it. One pull request per addition.

1. Put it in the right section, alphabetical where the section already is.
2. Format: `{ name: 'Name', url: 'https://…', blurb: 'Short neutral description.' }` — one
   sentence, ending in a period, **no marketing superlatives**.
3. Only tools that are live, publicly available and relevant to agency or service-business
   client work.
4. **Disclose any affiliation.** If you work for the tool, or are paid by it, say so in the
   pull request and add a `disclosure` line to the entry. The ClientOS entry carries one.
5. Check the link works. Dead links are removed.

Inclusion is not an endorsement and the list is not ranked. We do not accept payment for a
listing, and a pull request that offers it will be closed.

## Fixing a fact

This is the most useful kind of contribution. Every claim on the site is supposed to be
traceable to a primary source — see [AUDIT.md](AUDIT.md) for ClientOS and the two reachable
competitors, and [UNVERIFIED.md](UNVERIFIED.md) for what deliberately is not claimed.

If something is wrong or out of date:

- **Open an issue with the source.** A link to the vendor's own page is enough, and a date
  helps. Prices change often and we would rather hear it from you than be wrong for a quarter.
- **Vendors: this applies to you too.** If your own pricing page says something different from
  what we have, tell us and we will fix it. We will not, however, remove an accurate
  comparison.
- Facts live in `src/content/` — `site.ts` for ClientOS, `alternatives.ts` for comparisons,
  `faq.ts` for the FAQ. Update the data and the pages follow.

Competitor claims must come **only from that competitor's own public pages**, with the date
checked. Review sites, listicles and screenshots of old pricing are not sources here.

## Templates

Templates live in **`src/content/templates.ts`**. The files in `templates/` and
`public/downloads/` are generated by `pnpm build`, so edit the content file and let the build
write them.

Templates must be original or CC0-compatible, practical, and **vendor-neutral** — they should
be useful to someone who will never run ClientOS.

## Site changes

```bash
pnpm install
pnpm dev
pnpm build && node scripts/check-links.mjs   # must pass
pnpm check                                    # must be clean
```

If you add a page, run `pnpm og` to render its social card, and commit the PNG.

`check-links.mjs` will fail the build if a page is missing a canonical, a description, an
`<h1>` or an `og:image`, if a title runs past 70 characters, if an internal link is broken, or
if a rating claim appears anywhere — getclientos.com publishes no rating, so one here would be
invented.
